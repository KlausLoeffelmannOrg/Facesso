# Facesso — Technical Documentation: Registry, Licensing & Security

## 1. Registry Keys

Facesso stores its configuration and licensing data in the Windows Registry. Most values are written to both `HKEY_LOCAL_MACHINE` (HKLM) and `HKEY_CURRENT_USER` (HKCU) for redundancy (HKLM writes may fail without admin privileges; HKCU is used as fallback).

### 1.1 Main Application Keys

| Registry Path | Value Name | Type | Purpose |
|---|---|---|---|
| `HKLM\SOFTWARE\ActiveDev\Facesso\Classes` | `RegObject` | `Boolean` | Whether the application has been registered (setup completed). |
| `HKLM\SOFTWARE\ActiveDev\Facesso` | `Registered` | `Boolean` | Mirror of `RegObject` registration flag. |
| `HKLM\SOFTWARE\ActiveDev\Facesso` | `ForceReapplication` | `Boolean` | When `True`, forces re-registration on next start (set when date manipulation or license expiry is detected). Also mirrored under `HKCU`. |
| `HKLM\SOFTWARE\ActiveDev\Facesso\Classes` | `{face2470-bae0-20cd-b579-08002b30bfeb}` (VERSION_GUID) | `String` | The program's unique GUID, generated at first installation. Used as input for serial/license computation. |
| `HKLM\SOFTWARE\ActiveDev\Facesso\Classes` | `SerialNumber` | `String` | The entered serial number. Normally this is a 30-character base-20 string; for the testing bypass it can also be the literal universal GUID value from `UNIVERSAL_INST_SERIAL_MIT_FOR_TESTING`. Default: `"000000000000000000000000000000"`. |
| `HKLM\SOFTWARE\ActiveDev\Facesso\Classes` | `ConnectionString` | `String` | SQL Server connection string for the Facesso database. |

### 1.2 Date Tracking Keys

These track installation and runtime dates. The "Intel_lAD" paths use obfuscated key names to deter tampering; the human-readable copies under `ActiveDev\Facesso` are for convenience.

| Registry Path | Value Name | Type | Purpose |

| `HKLM\SOFTWARE\ActiveDev\Facesso` | `InstallationDate` | `String` | Installation date (human-readable copy). |
| `HKLM\SOFTWARE\Intel_lAD\Classes\{face0100-bae0-20cd-b579-08002b30bfeb}` | `DRL_Intel_Private` | `String` (OADate) | Last run date (obfuscated). |
| `HKLM\SOFTWARE\ActiveDev\Facesso` | `LastRunDate` | `String` | Last run date (human-readable copy). Also mirrored under `HKCU`. |
| `HKLM\SOFTWARE\Intel_lAD\Classes\{face0100-bae0-20cd-b579-08002b30bfeb}` | `DgeRL_Intel_Private` | `String` (OADate) | Last registered date (obfuscated). |

## 2. Licensing & Serial Number System

### 2.1 Overview

Facesso uses a hardware-bound licensing scheme implemented in `ADLicenseManager` / `FacessoLicenseManager`. The serial number ties the software to a specific hardware configuration. The process involves:

1. **Pre-Serial** — computed from hardware info + program GUID + installation date.
2. **Final Serial** — generated by the vendor from the pre-serial + license parameters.
3. **Validation** — at each startup, the hardware is re-read and the serial is re-validated.

### 2.2 Universal Testing Serial (Bypass)

The constant `UNIVERSAL_INST_SERIAL_MIT_FOR_TESTING` is defined as:

```
{face2407-6913-1068-1111-43002b30bfeb}
```

When this exact value is stored as the serial number, `RegistryHelper.IsUniversalTestingSerial()` recognizes it. `FacessoLicenseManager` then short-circuits both `HasValidSerialNo()` and `IsLicensed()`, so the hardware-bound comparison is skipped and the installation is treated as licensed. For predictable behaviour the in-memory license profile is also replaced with an unlimited Enterprise-style `ADLicenseInfo`. This is intended for development and testing purposes only.

### 2.3 Pseudo Code: Hardware Key Calculation

```text
FUNCTION GetPreSerialNo(programGuid, installationDate):
    // Step 1: Read the first hard-disk identity
    diskFingerprint = ""
    FOR EACH disk IN WMI("select * from Win32_DiskDrive"):
        diskFingerprint =
            SafeRead(disk["Model"], "JeDF59KK") +
            SafeRead(disk["Signature"], "SdFFg3Ed")
        BREAK

    // Step 2: Read the first base-board identity
    boardFingerprint = ""
    FOR EACH board IN WMI("select * from Win32_BaseBoard"):
        boardFingerprint =
            SafeRead(board["Product"], "XdFeR45") +
            SafeRead(board["Version"], "5GhzU87")
        BREAK

    // Step 3: Build the fingerprint text
    fingerprintText =
        diskFingerprint +
        boardFingerprint +
        programGuid.ToString() +
        installationDate.ToString()

    // Step 4: MAC/hash it with the fixed secret phrase
    mac = MACTripleDES(UTF8("Nicht genügend Speicher!"))
    hashBytes = mac.ComputeHash(UTF8(fingerprintText))

    // Step 5: Use the first 8 bytes as UInt64 and encode base-20
    preSerialNumber = BitConverter.ToUInt64(hashBytes, 0)
    RETURN Base20(preSerialNumber).PadLeft(15, "0")
END FUNCTION
```

### 2.4 Pseudo Code: Final Serial Generation (Vendor Side)

```text
FUNCTION GenerateSerialNumber(preSerialString, licenseInfo):
    licenseValue = licenseInfo.CompleteStructure   // UInt64

    // Step 1: Derive the MAC key from the license structure + registration date
    keyString = Base20(licenseValue).PadLeft(16, "0") +
                Date.Today.ToString("ddMMyyyy")
    mac = MACTripleDES(UTF8(keyString))

    // Step 2: Hash the pre-serial and keep the first 8 bytes
    serialHash = mac.ComputeHash(UTF8(preSerialString))
    serialValue = BitConverter.ToUInt64(serialHash, 0)
    serialPart = Base20(serialValue).PadLeft(15, "0")

    // Step 3: Obfuscate the raw license structure with a fixed XOR mask
    encodedLicenseValue = licenseValue XOR 0xFFEEDDCCBBAA9988
    licensePart = Base20(encodedLicenseValue).PadLeft(15, "0")

    RETURN serialPart + licensePart
END FUNCTION
```

### 2.5 Pseudo Code: Serial Validation (Client Side)

```text
FUNCTION ValidateSerial(programGuid, installationDate, lastRegisteredDate, serialString):
    IF serialString == UNIVERSAL_INST_SERIAL_MIT_FOR_TESTING THEN
        RETURN VALID
    END IF

    cleanedSerial = serialString.Replace(" ", "0").Replace("-", "")

    // Step 1: Split the serial into hash-part and license-part
    givenSerialValue  = ParseBase20(cleanedSerial[0..14])
    givenLicenseValue = ParseBase20(cleanedSerial[15..29])

    // Step 2: Recover the original license structure
    rawLicenseValue = givenLicenseValue XOR 0xFFEEDDCCBBAA9988
    licenseInfo = ADLicenseInfo(rawLicenseValue)

    // Step 3: Recompute what the hardware-bound serial hash should be
    keyString = Base20(rawLicenseValue).PadLeft(16, "0") +
                lastRegisteredDate.ToString("ddMMyyyy")
    mac = MACTripleDES(UTF8(keyString))
    preSerial = GetPreSerialNo(programGuid, installationDate)
    expectedSerialBytes = mac.ComputeHash(UTF8(preSerial))

    // Step 4: Compare expected bytes with the supplied serial bytes
    IF BitConverter.GetBytes(givenSerialValue) == expectedSerialBytes[0..7] THEN
        RETURN VALID
    ELSE
        RETURN INVALID
    END IF
END FUNCTION
```

### 2.6 License Info Structure (`ADLicenseInfo`)

| Field Offset | Size | Name | Description |
|---|---|---|---|
| 0 | 1 byte | `SoftwareID` | Product/edition ID. The serial generator historically emits values `1..6`; the Facesso runtime currently interprets `4=Light`, `5=Standard`, `6=Professional`, `7=Enterprise`, and still maps legacy `2` to Enterprise in `FacessoVersionPermissionInfo`. |
| 1 | 1 byte | `MonthsLimited` | Months until expiry (0 = unlimited) |
| 2 | 1 byte | `Limit1` | Max concurrent users |
| 3 | 1 byte | `Limit2` | Max internet users |
| 4 | 2 bytes | `Limit3` | Max employees |
| 6 | 2 bytes | `Limit4` | Extra feature/interface expansion value ("Schnittstellenausbau") |
| 8 | 1 byte | `HasFallenBack` | Runtime-only flag; not part of the encoded 64-bit serial payload |

### 2.7 Fallback Behavior

When the serial is invalid, `FacessoLicenseManager` calls `myLicenseInfo.Fallback(1, 2)`. Because `ADLicenseInfo.Fallback()` enforces a minimum of **2 months**, the effective fallback is:
- **Edition:** legacy ID `2` (treated as Enterprise by `FacessoVersionPermissionInfo`)
- **Time limit:** 2 months from installation date
- After expiry, the software throws `ADLicenseUnvalidException` and forces re-registration.

## 3. Super Administrator (System Account)

### 3.1 Password

During database setup (`frmSetupWizard` / `frmDbSetupWizard`), a hidden system account is created alongside the user-chosen admin account. The system account password is derived from hardcoded string fragments:

```
locString1 = "MSI!=Mainboard Creation Computer"
locString2 = "Cuslaka, Alfred"
locString3 = "2cp3b - Fargoroad"

locString2 = locString1.Substring(0, 4) + locString2.Substring(0, 4)
           = "MSI!" + "Cusl"
           = "MSI!Cusl"

systemPassword = locString2 + locString3.Substring(0, 5) + "f"
               = "MSI!Cusl" + "2cp3b" + "f"
               = "MSI!Cusl2cp3bf"
```

**The Super Administrator (system account) password is: `MSI!Cusl2cp3bf`**

This password is then hashed using the salted SHA1 mechanism (see below) and stored via the `InitializeDatabase` stored procedure as `@CryptedSystemPassword`.

### 3.2 ClearanceLevel for Admin

The highest clearance level is `Admin = &HFFFFFFFFFFFFFFFF` (all 64 bits set), granting full access to all system functions.

## 4. Password Hashing (`ADCryptedPassword`)

Facesso uses a **salted SHA-1** hash for storing user passwords in the database.

### 4.1 Algorithm

```
FUNCTION HashPassword(plainTextPassword):
    // Step 1: SHA-1 hash of the plain-text password (UTF-8 encoded)
    unsaltedHash = SHA1(UTF8.GetBytes(plainTextPassword))
    // Result: 20 bytes

    // Step 2: Generate 4 random bytes as salt
    salt = CryptoRandom(4 bytes)

    // Step 3: Concatenate unsalted hash + salt, then SHA-1 again
    rawSalted = unsaltedHash + salt            // 24 bytes
    saltedHash = SHA1(rawSalted)               // 20 bytes

    // Step 4: Append salt to the salted hash for storage
    dbPassword = saltedHash + salt             // 24 bytes total

    RETURN dbPassword
END FUNCTION
```

### 4.2 Verification

```
FUNCTION VerifyPassword(plainTextInput, storedDbPassword):
    // Step 1: Extract the 4-byte salt from the end of the stored password
    salt = storedDbPassword[20..23]

    // Step 2: Hash the input using the extracted salt
    inputHash   = SHA1(UTF8.GetBytes(plainTextInput))
    rawSalted   = inputHash + salt
    saltedInput = SHA1(rawSalted) + salt      // 24 bytes

    // Step 3: Byte-by-byte comparison
    RETURN storedDbPassword == saltedInput
END FUNCTION
```

### 4.3 Storage

Passwords are stored as `BINARY` columns in the `[Users]` SQL Server table. The total stored size is **24 bytes** (20-byte salted SHA-1 hash + 4-byte salt).

## 5. User Authentication Flow

1. User enters username, password, and selects a subsidiary in `frmLogin`.
2. `UserInfo` constructor queries: `SELECT * FROM [Users] WHERE [IDSubsidiary]=@id AND [Username]=@name AND [IsCurrent]=1`.
3. The stored `Password` (byte array) is loaded and wrapped in `ADCryptedPassword`.
4. The entered plain-text password is compared using the salted SHA-1 verification.
5. If matched → `Authenticated = True`; otherwise login fails with a reason message.
